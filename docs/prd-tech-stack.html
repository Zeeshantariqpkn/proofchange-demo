1. Problem Statement

CI answers: "Did the configured tests pass?"
It does not answer: "Is the newly changed behavior adequately verified?"

A pull request can introduce a new branch, a new execution path, or a new edge case while CI stays entirely green — because the existing test suite never exercises the new code. The tests were written for the old behavior. No test ever fails. The change ships unverified.

This is not a test-quality problem. It is a test-coverage blindspot at the point of change, and every team that relies on CI as its only safety signal has it.

2. Solution

ProofChange is an AI-powered verification layer that closes the gap between "CI passed" and "this change is verified." Its core output is a Change Evidence Package — a structured, machine-readable artifact produced automatically for every pull request.

Key insight: Test generation is step 5 of 7. ProofChange first proves a gap exists (steps 1–4) and then proves the gap is closed (steps 6–7). The generated test is evidence, not the product.

3. Core Pipeline (8 Stages)

1

Diff Analysis

Parses the unified diff — extracts changed files, line ranges, added conditionals.

engine/diff_analyzer.py → DiffAnalysis
2

Code Analysis

Python AST walk — maps functions, branches, return paths, source file paths.

engine/code_analyzer.py → CodeAnalysis
3

Test Mapping

Links existing tests to affected functions by name heuristics and docstring scan.

engine/test_mapper.py → TestMap
4

Gap Detection

Finds branches with no mapped test scenario. Promotes security-keyword branches to HIGH severity.

engine/gap_detector.py → list[TestGap]
5

Test Generation IBM Bob

Produces focused pytest scaffolds targeting each detected gap. Bob-assisted workflow.

ai/test_generator.py → list[GeneratedTest]
6

Execution

Runs real pytest against the generated tests. Captures pass/fail/skipped/duration.

engine/runner.py → ExecutionResult
7

Impact Analysis

Classifies affected paths as verified / partial / unresolved. Deduplicates by (source_path, fn_name).

engine/impact_analyzer.py → PathSummary
8

Evidence Package

Aggregates all pipeline outputs into a scored, timestamped, machine-readable artifact.

engine/evidence.py → EvidencePackage (JSON + Markdown)

4. Evidence Levels

✓ Strong

All gaps addressed + ≥70% paths verified + all tests passed

⚠ Partial

Some gaps addressed or some paths unverified

✕ Insufficient

Tests failed or gaps remain unaddressed

Evidence level is computed by explicit, auditable rules — not an LLM opinion. Every level carries a plain-language rationale string.

8. Differentiation vs. AI Test Generators

DimensionAI test generatorsProofChange
ScopeWhole repo or arbitrary promptScoped to the specific change in the PR
Input"Generate tests for this file"The diff itself — change is the anchor
OutputTest code suggestionsScored Change Evidence Package
Gap detectionNot performed — tests generated speculativelyAST-driven — gaps detected before generation
ExecutionUsually not includedReal pytest execution is a mandatory pipeline step
VerdictNone — user decidesSTRONG / PARTIAL / INSUFFICIENT with auditable rationale
AI roleAI is the productAI assists the pipeline — engine runs deterministically without it
